Think of this as starting a new chapter in a book — before you write anything, you give the chapter a title, add it to the contents page at the front, and set up a blank page for it to live on. That's exactly what this does, in one go.

The HTML — two pieces, two destinations

This is the one block that produces two separate outputs, because a table of contents entry and the actual section live in two different places on the page. The section wrapper:

<section id="putting-into-practice">
  <h2>Putting into practice</h2>

  (content goes here)

</section>

...and, separately, the matching table of contents entry:

<li><a href="#putting-into-practice" class="toc-link">Putting into practice</a></li>

Notice the id (putting-into-practice) and the link's href are exactly the same text — that's what makes clicking the table of contents entry actually jump down to this section. Both get built from the same title you type, once, so there's no way for them to quietly drift apart the way hand-typed ids sometimes do.

The "directly below the page title" tick box

Headings normally keep a generous gap above them. That's right between sections, but when the very first section sits straight under the page title (a page with no At a glance box) the gap looks too big. Ticking the box adds class="tight-heading" to the heading, and the Base CSS pulls it up. Leave it unticked for every other section, and for pages that do have an At a glance box.

Where the other blocks fit in

The comment in the middle — <!-- Content goes here --> — is where you paste whatever you build on the other tabs: an image-text-section, an accordion, at-a-glance, anything. One section can hold more than one block if the content calls for it; just paste them one after another in place of the comment.

Why there's no CSS output for this one

Unlike every other tab, this block doesn't need its own CSS — spacing, scroll behaviour and heading styles for sections are already part of the Base CSS every page starts with, so there's nothing extra to add.
