Two styles live in this one block, chosen once for the whole row via "Card style":

Style 1 — Icon + description + button

Three (or however many) signposts side by side — an icon, a line explaining what's over there, and a button to actually go. The important bit: only the button is clickable, not the whole card — unlike resource-cards, where the entire card is one big link.

<div class="nav-card">
  <div class="nav-card__icon">
    <img src="..." alt="" />
  </div>
  <p>Learn what compassionate leadership means</p>
  <a href="..." class="nav-card__button">Understand it</a>
</div>

Notice the <img> and the <a> button are separate elements, not nested inside one another — that's the structural difference from resource-cards, where the whole card is one clickable link. Here, clicking the icon or the description text does nothing; only the green button is an actual link.

The circle behind the icon (style 1 only)

The navy circle isn't part of the icon image at all — it's plain CSS, a box made perfectly round with border-radius: 50%, coloured navy, with the icon centred inside it using flexbox. That's why the icon itself needs to be a transparent PNG: the navy circle is the actual background, showing through wherever the icon image is transparent. A white-icon-on-transparent-background PNG is what makes this look right — a PNG with its own solid background would show up as an ugly box over the circle instead of blending in.

New tab, off by default (style 1 only)

Unlike buttons and resource-cards (which default to opening in a new tab), this block defaults to the same tab — matching the reference design, where these are meant to feel like in-site navigation rather than links out to something external. Ticking the box adds target="_blank" and the little arrow icon, same as everywhere else.

Style 2 — Numbered heading + plain icon

No visible button — but the whole card is clickable, using the same trick as resource-cards.

<div class="nav-card nav-card--numbered">
  <a href="..." class="stretched-link" aria-label="..."></a>
  <h3><span class="nav-card__number">1.</span> Agree direction and ensure alignment and commitment</h3>
  <div class="nav-card__icon-plain">
    <img src="..." alt="" />
  </div>
</div>

That empty <a class="stretched-link"> has no visible content of its own — stretched-link is what invisibly expands its clickable area to cover the entire card, the same way resource-cards works. The aria-label is filled in automatically from the heading text, so a screen reader still announces something meaningful even though there's no visible link text to read. Hovering the card lifts it slightly and adds a shadow (matching the lift effect used on resource cards and icon-toggle triggers), and the cursor switches to a pointer — both there specifically to signal "this whole box is clickable" even though nothing looks like a traditional button.

Two more things worth knowing: the icon here has no navy circle behind it — these icons are already full-colour transparent PNGs with their own colours baked in, so no CSS circle is needed or wanted. And numbering is automatic (a checkbox, on by default) rather than typed — the number is based on each card's position, so reordering or removing a card never leaves you with "1, 3, 4" or a stale number stuck on the wrong card.

How the icon always sits at the bottom

margin-top: auto on the icon's wrapper is a neat flexbox trick — inside a flex column, an automatic margin greedily eats up all the leftover space above it, pushing everything after it to the very bottom of the box. That's what keeps the icons lined up at the bottom of every card even when headings run to different lengths.
