Imagine a row of light switches: flick one, and a message board underneath lights up with that switch's message. Flick a different one, and the board swaps to the new message — only one message shows at a time.

The HTML

<div onclick="openAccordion(this, 'content-hosting-a-meeting')" ...>
  <div class="data-icon-card">
    <img src="..." />
    <h5>Hosting a meeting</h5>
  </div>
</div>

<div class="content-display" id="content-hosting-a-meeting">
  (content goes here)
</div>

Clicking an icon calls a function called openAccordion, telling it two things: "here's the icon I clicked" and "here's the id of the panel it should open" — like calling a friend and saying "open that box, and close whatever else is open." That id has to match the panel's own id exactly, which is why the tool generates both from the same label text automatically.

Why the JS is separate from the HTML/CSS

Unlike the accordion (which reuses Bootstrap's own built-in behaviour), this block needs its own small helper function — openAccordion — that isn't part of Bootstrap. It only needs to exist once on the page no matter how many icons you add, which is why it's pasted into the shared script area rather than repeated per icon — like one shared tool in a toolbox, not a new copy for every job.

The scroll behaviour

When a panel opens, the page automatically scrolls down to it (scrollIntoView) — with some extra breathing room added above it, deliberately, so the icon you just clicked stays visible on screen. That way you can find it again to close the panel without having to scroll back up.
